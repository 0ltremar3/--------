# 凭据更换操作说明

按用户要求，密钥由用户更换。本说明不含任何密钥值，本次尚未执行凭据轮换。

## 先确认是哪套账号

已回读 healthmall 云端 `uni-config-center`，与误上传副本在本机逐项比较：

- 当前 `tokenSecret` 与 `passwordSecret` 和误上传版本相同，应优先处理。
- 当前微信小程序 AppSecret、支付 APIv2 密钥和商户证书与误上传版本不同；支付配置的 AppID、商户号也不同。这不能证明旧账号的凭据已失效，应按误上传配置所属的 AppID／商户号重置或撤销，避免操作错账号。
- 若实际使用 uni 一键登录，也检查并更换其 `service.univerify.apiKey`。未启用的示例配置不应被当成当前生产凭据。

请以**云端当前配置**为基础修改，不要把管理端旧配置整份覆盖上去。云端回读备份位于本机受限目录：

`/Users/ryuchiang/.codex/deployment-backups/healthmall-security-recovery-20261029/security-before-20261029/uniCloud-alipay/cloudfunctions/common/uni-config-center/`

它是操作前快照；真正更换之前应再次核对云端是否已有其他变更。不要把密钥或上述目录发到聊天、Git、截图或网页托管。

## 1. 登录签名密钥

修改 `uni-config-center/uni-id/config.json` 中的 `tokenSecret`。在本机终端生成独立的新随机值，例如运行 `openssl rand -hex 32`，将结果只保存进受保护配置。

上传到 healthmall 的是 **uni-config-center 公共模块**，并更新其云端依赖函数。新密钥生效后，旧登录令牌会失效，管理员和用户需要重新登录。先确认自己拥有可用的管理员登录方式。

官方说明：[uni-id 配置与密钥修改](https://doc.dcloud.net.cn/uniCloud/uni-id/summary.html)。

## 2. 密码加密密钥：采用版本迁移

不要直接把字符串 `passwordSecret` 改成另一个字符串，否则旧密码会验证失败。

先备份配置与用户密码相关字段，并检查 `uni-id-users.password_secret_version`。若当前使用单一旧密钥、用户没有版本字段，采用如下结构（下方只是占位说明，不可原样上线）：

```json
"passwordSecret": [
  { "version": 1, "value": "原来的密钥值" },
  { "version": 2, "value": "单独生成的新随机密钥值" }
]
```

若已有版本配置，保留全部仍被用户使用的旧版本，并追加一个更高版本。旧用户成功用密码登录后，uni-id 会将其密码记录升级为新版本。没有版本字段的用户仍使用最旧版本；只有确认没有用户依赖旧版本后，才能移除它。管理员应尽快登录完成迁移并更换密码。仍保留的旧密钥属于迁移阶段，不能称为已经完全撤销。

依据：[DCloud 的 passwordSecret 迁移机制](https://doc.dcloud.net.cn/uniCloud/uni-id/summary.html)。

## 3. 微信 AppSecret

在微信公众平台切换到需要处理的 AppID，在开发设置／开发接口管理中找到 AppSecret 并重置，按页面要求完成管理员验证。

如果该 AppID 正在此商城使用，同步更新云端配置中的：

- `uni-id/config.json` → `mp-weixin.oauth.weixin.appsecret`。
- `uni-pay/config.js` → `wxpay.mp.secret`（与该 AppID 对应时）。

如该 AppID 还有其他服务器或授权应用，也同步更新。上传公共模块并更新依赖函数后，验证微信登录、手机号授权和商品分享。AppSecret 更新无需把新密钥放进小程序前端。

## 4. 微信支付 API 密钥和商户证书

本商城当前支付配置为 `version: 2`，使用 **APIv2 密钥**。进入对应商户号的微信支付商户平台，查找“账户中心 → API安全”，重置 APIv2 密钥；同步配置 `uni-pay/config.js` 的 `wxpay.mp.key`。只修改 APIv3 密钥不会修复 APIv2 凭据的暴露问题。

证书泄露应申请新证书，在部署新证书并验证后作废旧证书，不能只换 API 密钥。当前 Node 配置读取 `.p12`；替换时检查 `uni-pay/wxpay/apiclient_cert.p12`，以及实际使用的 `apiclient_cert.pem`、`apiclient_key.pem`，确保全部来自正确的新证书和商户号。

微信官方操作入口是“账户中心 → API安全 → 管理证书”。安全验证可能要求超级管理员、操作密码或短信验证码，需本人完成。详见[更换及作废商户 API 证书](https://pay.weixin.qq.com/doc/v3/merchant/4013053057)及[APIv2 安全规范](https://pay.weixin.qq.com/doc/v2/merchant/4011985891)。

如果误上传的是已停用的旧商户配置，直接在旧商户平台确认撤销对应证书／旧密钥；不要把旧商户的新凭据覆盖到现在使用的另一个商户号上。

## 完成后的验证

先验证管理员重新登录、小程序微信登录、商品浏览，再进行经你确认的小额支付、支付回调及退款测试。仅“上传成功”不等于支付链路恢复。同步更新两端实际用于部署的配置，避免下一次部署恢复旧密钥；保留受限备份，禁止上传整个源码项目到静态托管。

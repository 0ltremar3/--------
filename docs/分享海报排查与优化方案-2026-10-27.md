## 4. 先实现制码、缓存与 scene 解析服务

建议新增最小云对象 `uniCloud-alipay/cloudfunctions/jlg-share/index.obj.js` 及其 `package.json`；命名可顺应仓库惯例调整，但以下契约和行为须保持。客户端统一通过一个小 helper 调用，两个页面复用。

### 接口契约

| 方法 | 输入 | 成功输出 | 权限与行为 |
|---|---|---|---|
| `getProductCode` | `{ goodsId, envVersion }` | `{ errCode: 0, scene, fileID, envVersion, width }` | 登录校验后从 token 获取推广人 uid；校验商品存在且可分享；固定微信 AppID、page、宽度由服务端配置；命中缓存直接返回 |
| `resolveScene` | `{ scene }` | `{ errCode: 0, goodsId, sharerId, envVersion }` | 允许未登录扫码解析，仅返回落地所需字段；非法、未知、停用标识返回明确业务错误，不产生绑定或订单写入 |

错误沿用项目约定，提供可识别的错误码和可展示文案；覆盖未登录、参数无效、商品不可用、配置缺失、制码中、微信调用失败及超时。客户端若直接传入推广人 ID，不作为可信身份来源。制码入口增加按用户限制生成频率或数量的轻量保护，缓存命中不重复消耗微信制码请求。

### 微信请求与环境

使用 `wxacode.getUnlimited`（`/wxa/getwxacodeunlimit`）。目标请求形状为：

```json
{
  "page": "pages/product/product",
  "scene": "持久化的短标识",
  "env_version": "trial",
  "check_path": false,
  "width": 1024
}
```

- 微信客户端读取运行环境并明确传 `develop` / `trial` / `release`；服务端只接受允许列表中的值，缓存按环境隔离。测试部署先允许 trial；开发者工具确需 develop 时再配置，不把正式客户端静默导向体验版。
- H5 没有微信运行环境 API，使用明确的部署配置；本轮测试配置为 trial，正式发布清单中改成 release，不凭 User-Agent 猜测。
- trial/develop 使用 `check_path: false`，页面仍必须存在于对应已上传版本；release 使用正式已发布页面并开启路径校验。
- `page` 不带前导斜杠或 query，scene 使用允许字符内的短标识（例如 24 位随机十六进制），不直接拼接两个长数据库 ID。
- 1024px 为独立保存/包装打样的拟定源图尺寸，海报内缩小绘制；实现时核对接口当前允许值。保存保留微信原图，不重绘图案或裁掉外部留白。
- 复用 `uni-open-bridge-common` 的凭据缓存及配置。微信凭据仅存在服务端；token 失效最多刷新重试一次，其他错误不无限重试。
- 验证微信响应的状态、内容类型/图片签名与 JSON 错误体，确认是有效图片才上传。返回错误 JSON 时不得伪装成 PNG 缓存。

上次核对时微信官方制码文档未能直接读取；参数以执行时的官方文档和真实接口结果再次确认。可先按上述契约写模拟测试，不以文档暂时不可达为由停止本地开发。参考 [微信制码文档](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/qrcode-link/qr-code/getUnlimitedQRCode.html)、[EasyWeChat 调用示例](https://easywechat.com/6.x/mini-app/examples.html)。

### 持久映射与缓存

新增一个专用集合（建议 `jlg-share-codes`），配套 schema 和所需唯一索引。最小字段：`scene`、唯一缓存键、`goodsId`、`sharerId`、微信 AppID、page、envVersion、码版本/尺寸、fileID、生成状态及时间戳。客户端直接读写关闭，统一走上述云对象。

缓存键包含：微信 AppID + 环境 + page + 商品 ID + 推广人 ID + 码规格版本。价格、昵称、语言不影响码的目的地，不放进码缓存键。

1. 先保证 scene 映射持久存在，再返回对应图片；同一键并发请求通过唯一索引/原子认领复用同一记录和 scene。若使用生成中状态，设置可恢复的短租约，进程退出后仍可重试。
2. 服务端保存稳定 fileID；客户端按需解析可用图片地址并下载。签名 URL 过期时重新解析，不重新申请微信码。文件确实丢失时，使用原 scene 重建图片。
3. 成功缓存仅包含可用文件；生成、上传或回写失败都能恢复，清理无引用的失败产物，不误删其他成功任务的文件。
4. 包装码映射长期保留，不因缓存清理或价格更新删除。商品下架/删除后给出明确不可用状态；映射损坏时不静默跳首页，也不把旧 scene 指向另一商品/推广人。
5. 配置缺失时返回可定位错误，保留官方码路线，不回退到旧测试域名二维码。

**本阶段完成条件**：模拟验证命中缓存不调用微信、不同推广人/环境不串码、并发不生成多份有效映射、失败可恢复、匿名解析可用且制码必须鉴权；缺凭据时本地测试仍能运行。

## 5. 打通扫码落地和推广归因

1. 在商品页统一解析入口，优先处理存在的 `scene`，再兼容旧 `id`/`fxsid`/`q`。scene URL 解码要捕获异常；非法 scene 明确失败，不用同时传入的 id 偷换落地商品。
2. scene 解析成功后，仅触发一次商品、评价等加载流程。避免新增异步解析与旧 onLoad 两个分支重复初始化；商品失效有可返回的错误页/提示。
3. 将有效 `sharerId` 接入现有 `dicrID`/分销绑定链路；校验空值，避免存入字面量 `null` 或 `undefined`。客户端存储来源不是服务端授权凭据。
4. 逐一验证未登录扫码后登录、已登录扫码、已有上级、自我扫码、推广人不具备资格及重复扫码。采用现有首次有效绑定规则；已有关系不覆盖，自我绑定不成立。无效扫码不得误用残留推广人发起绑定。
5. 已登录用户不能只写缓存后等待一个不会发生的登录事件；在身份就绪时按现有规则尝试绑定。未登录用户在登录成功后再尝试。绑定拒绝不影响正常浏览商品，结果须能区分成功、已有关系、不满足条件和服务异常。
6. 若需要修改 `jlg-distribution.add` 或登录成功钩子，先检索所有调用者，只修复此链路必需的校验、结果语义和异常：服务端验证当前登录用户，不信任客户端传入的被绑定用户 ID；保留佣金比例、层级和结算规则。

**本阶段完成条件**：测试证明 scene → 正确商品 → 正确推广来源贯通，且新旧参数不冲突、两种登录状态均可处理、关系不被错误覆盖。

## 6. 改造两处分享入口和海报组件

### 用户操作和任务生命周期

- 两个入口均提供“生成海报”和“保存商品码”；商品码可先预览再由用户触发保存，海报失败不影响已生成的码。体验版/开发版在预览区明确标注“测试用，勿用于正式包装”，标签放在图片外，保持码图片完整。
- 打开分享面板时按需准备当前商品码和主图；分销列表只准备用户选中的商品，不批量预生成所有用户×商品的码。
- `showCanvas`/生成方法返回可等待的 Promise；二维码准备、图片准备、绘制、导出全链路都有失败处理。UI 操作统一 finally 收尾，失败可重试；当前任务才有权关闭自己的 loading。
- 同一内容重复点击复用进行中的 Promise。关闭、页面卸载、切换商品/账号后使旧任务失效，迟到结果不得覆盖新状态或重新打开弹层。底层能取消则取消；不能取消的云请求允许服务端完成缓存，客户端忽略迟到结果。
- 从用户点击到图片就绪设置整体 8 秒等待上限。超时退出并显示可重试；相册授权与系统保存不计入这个生成计时。

### 素材、绘制与导出

- 删除未使用的头像下载；品牌图使用项目内现有品牌资源生成的小尺寸打包文件。保留昵称展示；如果后续要求真人头像再另行扩展，不让其阻塞本轮海报。
- 主图选择首张有效图片，兼容视频首项/空数组，回退到商品缩略图；仍无图则提示素材缺失，商品码仍可保存。H5 也传入同一主图，移除写死 Logo 的商品图分支。
- 图片与小程序码并行准备；主图优先使用已有缩略图/已验证 CDN 缩放能力，目标约 600–800px、200–300KB。不对未知 CDN 盲加参数，不为这项优化批量改商品数据；缺少合适缩略图时如实记录原图耗时。
- 海报素材入口支持已下载本地路径、Data URL 和已解析的远程 URL。按类型准备本地可绘制资源：仅 Data URL 解码，远程图下载/取图片信息，本地路径直接使用。
- 用视图更新、画布尺寸就绪和绘制完成回调替代业务层固定 500ms 等待；导出只在 success 中读取文件路径。可复用现有 Canvas，无需为了重构换库。
- 生成一份完整海报图片用于预览和保存；独立商品码保存原始高分辨率码图，不截取海报内的小图。
- H5 校验图片跨域与导出能力；微信浏览器按实际支持提供长按预览/下载。相关平台失败显示可操作提示，不能显示空图却报告成功。
- 保存处理首次授权、已授权、拒绝、重新授权、取消及失败。关闭/保存完成时统一通知父页面，解除页面滚动锁；清除组件内始终 overflow hidden 的状态错误。

### 客户端缓存

先用页面会话级缓存和进行中 Promise 复用，无需增加缓存依赖。素材按完整 URL/版本缓存；小程序码按服务端 scene/fileID + 环境缓存；海报按商品、推广人、码版本/环境、图片版本、标题/语言、价格/划线价、昵称及模板版本缓存。登录账号变化同步刷新身份并失效相关任务。

临时文件使用前确认可用；不存在就重新准备。仅清理本功能创建且不再使用的文件，避免每次重复写 Base64 文件造成积累。uQRCode 若无其他调用再移除页面引用；依赖清理以检索结果为依据。

# 购物袋付款后清理修复

## 原因与改动

此前购物袋进入结算时没有传入购物袋记录 ID，订单只记录商品／规格。支付结算更新订单状态和销量，但未更新购物袋。

- 购物袋仅将有效且选中的条目传入结算，同时传递 `cart_id`。
- 结算页的报价和支付商品参数保留 `cart_id`；直接购买不携带该字段。
- 交易服务在报价／创建订单时核对购物袋记录的所有者、商品、SKU 和普通／秒杀类型，在订单商品行中保存服务端生成的 `cart_sources`。不信任客户端直接传入的清理元数据。
- 服务端核验支付成功后，在同一事务中扣除来源记录的已购买数量；剩余数量为零时删除该条目。
- 仅处理支付前记录的来源条目；通过创建时间识别删除后重新加入的同 ID 记录，避免误删。
- 支付状态的幂等检查使重复通知不会再次扣除。取消／未付款不清理；订单列表继续付款仍使用订单保存的来源。
- 使用已有受保护的 goods_arr 数组保存来源快照，无新增数据库字段权限或集合。

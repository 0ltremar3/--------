# 购物袋优惠修复与运费明细优化方案

日期：2026-10-29。购物袋计算与运费方案均已实施。运费明细改为标签旁的灰色帮助入口及底部弹层。

## 1. 为什么出现“已优惠 -90 元”

原逻辑为「已选商品划线价合计 − 售价合计」。划线价为 0、售价为 9000 分时，结果为 -9000 分，即 -90 元；缺失字段还可能导致 NaN 或报错。已用该输入复现，未读取线上商品记录确认其划线价。

`crossed_price` 在数据库中定义为“划线价格，只做展示用”。这里展示的是相对划线价的价差，不是结算时已使用的优惠券，也不会再从应付金额中扣一次。截图中的商品 90 元加运费 12 元，实付款为 102 元，与负优惠展示无关。

修复位置：`pages/cart/cart.vue`。

- 按每件有效且已勾选的商品计算：仅当划线价是有效数值且高于售价，累计「（划线价 − 售价）× 数量」。
- 不用无划线价商品的负差额抵消其他商品的正常优惠。
- 优惠为 0 时隐藏整行；有优惠时保留两位小数。
- 空购物袋重新计算时清零金额和全选状态，避免残留上次金额。

保留现有“已优惠”命名；若后续统一优惠口径，可将参考价差改称“比划线价省”，与结算页优惠券抵扣明确区分。

## 2. 推荐运费布局

移除结算页底部独立运费明细卡。在商品卡片内，“运费”文字右侧放灰色圆圈帮助图标，金额继续右对齐：

```text
运费 ⓘ                         ¥12.00
                    商品小计：¥90.00
```

- 图标可见尺寸约 16px，灰色建议 `#757575`，不使用品牌绿强调辅助入口；与文字间距沿用 10rpx。
- “运费＋图标”作为一个可点击区域，实际触控区域至少 44 × 44px，不依赖精准点中小图标。可访问名称为“查看运费明细”。
- 点击打开底部弹层，复用项目已有 popup 组件；标题为“运费明细”，右上角关闭，支持遮罩关闭，保留底部安全区。
- 弹层内用普通文本和费用行，不再嵌套卡片。内容较长时内部滚动；长商品名换行，金额不换行。
- 外部边距采用 30rpx，条目间距 20rpx，相关说明间距 10rpx。正文沿用 26rpx，辅助说明 24rpx，文字使用足够对比度的灰色。

## 3. 本次截图对应的文案示例

以下以服务器返回“当前商品满 120 元包邮，商品金额 90 元，运费 12 元”为前提；不从后台模板名称解析规则。

```text
运费明细                          关闭

本单运费                       ¥12.00
配送至                         浙江省 杭州市

新会陈皮（5年）
包邮条件：参与商品满 ¥120.00
当前参与商品金额：¥90.00
还差 ¥30.00 满足包邮条件

包邮门槛按优惠前商品金额计算，
会员折扣和优惠券不影响门槛。
```

“参与商品”仅指同一运费规则下的商品，不能写成“全店再买 30 元即可包邮”。只有存在有效包邮门槛且当前仍需付运费时才显示差额；达到门槛后显示“已满足包邮条件”，不继续引导凑单。

## 4. 多种规则及异常状态

| 场景 | 展示与交互 |
| --- | --- |
| 仅一种运费规则 | 显示运费、涉及商品、有效包邮条件及差额；省略合并规则说明。 |
| 多种运费规则 | 按商品名称列出各项费用；补充“不同商品的运费分别计算，本单仅收取其中最高一笔。”例如 12 元和 8 元时收取 12 元。 |
| 某组尚差金额 | 写“本组还差 ¥X 满足包邮条件”；不能承诺凑齐该组后整单免运费。 |
| 固定运费、无包邮门槛 | 写“这些商品配送至当前地区，运费 ¥X。”不显示门槛或差额。 |
| 当前已包邮 | 页面金额显示“免运费”；明细显示相应包邮状态。 |
| 未选地址 | 运费显示“—”，在运费附近提供“选择收货地址”入口。 |
| 正在重算 | 显示“正在计算…”，不打开上一次报价的明细。 |
| 报价失败 | 运费附近显示服务端对应错误及重试／更换地址入口；不得误显示为免运费。 |
| 地址、商品或优惠变化 | 明细与当前有效报价同步；报价失效时关闭或清空旧明细。 |

数据复用 `quoteResult.freight_snapshot.groups` 的 `goods`、`amount`、`fee`、`threshold`、`remaining` 和整单 `freight`。后台模板名称不作为面向消费者的主要说明；多组仅用于解释不同商品适用的规则。

## 7. 优惠券取消入口调整

删除结算页独立的“取消已选优惠券”卡片。取消操作统一放在优惠券选择弹层：已选券显示“取消选择”，顶部“不使用优惠券”清空全部选择并返回结算页。即使券已失效、列表无可用券或商品变为秒杀，存在已选券时仍可进入弹层取消。取消后使用现有报价监听重新计算金额，迟到的旧优惠报价不会覆盖新结果。结算、运费、交易回归及共享代码同步检查通过。

## 8. 购物袋返回页面的选择状态

修复 `onShow` 清空商品选择、却保留底部全选状态的问题。同一账号离开购物袋后返回或下拉刷新，按购物袋记录 ID 恢复已选商品，并使用新价格、数量和可用状态重算合计与全选。新增商品默认不选；已失效商品取消选择；全部失效或空列表不会显示全选。移除首次进入时 onLoad/onShow 的重复请求，并拒绝过期请求覆盖新列表。切换账号或登录失效时清空原账号选择。

`node tests/checkout-ui.test.js` 已覆盖全选后返回、部分选择后刷新、列表重排、价格变化、新增／失效／删除商品、请求乱序与账号切换。状态保留范围为当前购物袋页面会话，不新增本地持久化或云端字段。

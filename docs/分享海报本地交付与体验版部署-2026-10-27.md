在微信开发者工具中使用本地素材复现，排除网络下载：旧实现会在画布挂载后将 canvas-id 从 share-canvas-0 改为任务编号。原生画布仍登记在旧 ID；对旧 ID 的纯色矩形 draw 有回调，对新 ID 没有，最终触发 8 秒总超时。另外，缓存命中重新 getImageInfo 时返回的包内路径失去前导 /，导致商品分包二次加载图片失败。原先 Node mock 未模拟原生 ID 注册和包内路径变化，未捕获此问题。

最终修复：

- 固定画布 ID，画布保持挂载；关闭、切换商品仍使任务失效，预览面板单独开关。
- 微信使用原生 Canvas 2D 节点，查询真实尺寸后按 pixelRatio 设置导出分辨率。图片加载成功后绘制、按同一节点导出，不再等待旧 CanvasContext.draw 回调。绘图上下文仅在当前任务内使用，不放进 Vue 响应式数据。
- 同一次绘图相同图片路径只解码一次，图片解码失败可定位；H5 保留现有画布导出流程。
- 包内 /static/ 路径在首次准备和缓存校验后均保留根路径。
- 8 秒总体上限保留；错误提示区分素材准备、画布就绪、图片解码、绘制及导出阶段。

新增回归：原生注册 ID 不随响应式数据改名，包内图片缓存命中路径，微信 2D 节点导出与设备像素比，图片解码失败/无回调，画布缺失/无回调，关闭重开与改价后的再次导出。原有海报、分享码、商品详情、审核整改、图片 URL、首页测试继续运行。

微信开发者工具运行验证使用页面内存中的本地测试商品，主图及码位置以品牌素材替代，不请求新微信码、不创建用户关系或订单：首次完整导出 904ms；同内容缓存预览 21ms；关闭重开 37ms；改价重新绘制 163ms。为单次本地样本，不代表网络耗时或真机 P50/P95。实际导出 PNG 为 1014×1683，已打开核验完整文字、价格、品牌和图片，不是空白图。

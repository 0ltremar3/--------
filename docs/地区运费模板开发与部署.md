# 地区运费模板：实现、验收与部署

## 已实现的业务口径

- 同模板的SKU售价×数量累计，会员折扣、优惠券不影响包邮门槛；秒杀按秒杀价。
- 首期按模板商品组固定收费；省级地区规则支持直辖市。
- 不配送优先；满足指定地区包邮条件后运费为0；否则取指定地区费或默认费。
- 每个模板独立算费，旧固定运费商品保持取最高值；整单取所有组最高运费，不相加。
- 包邮商品不会帮助其他模板凑单。任何不配送商品都会阻止整单提交。
- 模板不存在、删除或配置异常时拒绝下单，不回退到包邮。

## 代码与数据

用户端是共享交易服务源，运行 `node scripts/sync-commerce.js --write` 同步两端。同步范围包含新增 freight / freight-admin 模块、jlg-checkout、支付云对象、支付组件、模板schema及商品/订单新增schema字段。生成支付运行时仍沿用原脚本，不直接手工修改生成物。

后台：配送管理 → 运费模板，新增/编辑/复制/删除；商品编辑增加模板选择。菜单使用已有 `jlg-order-stat-setup` 的带备份预览、应用、回退机制，新增两个菜单定义，不授予或改变任何角色权限。模板操作允许 admin 或已有 GOODS_EDIT 权限。

新集合 `jlg-freight-templates` 禁止客户端直接读写，后台经授权云对象操作。地区来源为已有 `opendb-city-china`。商品新增 `freight_mode` 和 `freight_template_id`；未修改配送设置的旧商品不自动迁移。

模板关联、解除关联和删除在事务中同时更新模板 `binding_revision`，利用同文档写冲突防止删除/绑定竞态。软删除前检查引用。修改模板使用 `version` 防止覆盖他人修改。真实云空间的并发冲突行为仍需在测试环境验证。

订单新增 `checkout_version`、`quote_key`、`address_id`、`address_snapshot` 和 `freight_snapshot`，保留原 `freight` 与地址文本。

## 接口

`jlg-freight-admin`：list({page,keyword})（每页50条）、getDetail(id)、save(template)、copy(id)、remove({id,version})。

`jlg-checkout.previewFreight`：输入 goods_id、可选 sku_id / goods_suk、goods_num、goods_seckill、address_id 或 area_code。无SKU仅返回地区规则，freight为null。地区方式可匿名使用；地址ID必须属于当前登录用户。

`jlg-checkout.quote`：输入 goods_arr、address_id、preferential（优惠券ID列表）。用户身份仅从token获取。返回 goods_arr、origprice、deduprice、payable、freight、total_fee、preferential、address_snapshot、freight_snapshot、quote_key。业务错误以 error 对象返回，客户端 common/delivery.js 统一抛出；不配送错误包含 blocked_goods，保证云对象序列化不会丢失商品名单。

正式下单支付参数新增 address_id、checkout_version:1、quote_key。服务端重新读取配置并计算，报价指纹或金额不同返回 PRICE_CHANGED，用户确认新报价后重新提交。报价不占库存、不占券、不持久化报价表。

已创建订单续付按原快照，修改商品、地址、优惠需取消重下。整单退款保持原金额。旧客户端不带协议时，旧运费商品继续可买，模板商品返回 CHECKOUT_UPDATE_REQUIRED。

## 用户交互

商品页新增配送地区入口和地址面板。已有地址/新建地址/匿名省市区选择共享会话内选择；账号变化清空，不写默认地址。商品页只预估当前选择，不把购物车商品偷偷加进门槛。仅选地区进入结算时，必须选完整地址，不替换为其他地区的默认地址。

结算页改用服务端报价；地址/商品/优惠变更立即失效，计算中和错误状态禁用提交。请求序号及输入快照避免旧响应覆盖。优惠券可以再次点击取消，也可一键取消已选券。客户端报价展示、错误提示和运费说明含中英文资源。

## 测试空间与上线步骤

1. 备份即将绑定模板的商品：_id、freight、freight_amount、已有freight_mode / freight_template_id；备份菜单及当前服务版本。
2. 在测试云空间上传模板、商品、订单schema；确认行政区字典存在且包含省市区层级，不用整库初始化覆盖真实数据。
3. 上传用户端共享 jlg-commerce、jlg-checkout，上传管理端 jlg-freight-admin / jlg-goods-admin，以及更新后的 uni-pay-co。同步并重新部署引用公共模块的相关云函数；保留原支付参数与凭据。
4. 管理员调用 jlg-order-stat-setup.preview() 核对菜单差异，再调用 apply()，保存返回的 backupId。此工具会预览/处理既有经营看板菜单，因此应检查完整差异；只执行一次，不修改角色授权。已有商品编辑人员需要现有 GOODS_EDIT 权限才能使用新菜单。
5. 先发布用户端新结算，再发布后台模板和绑定入口。创建测试模板并只绑定测试商品。
6. 测试空间人工验证：模板CRUD、错误/重试、复制、绑定两种保存入口；匿名选地区、已有/新增地址；购物车与直接购买；119.99/120边界；换地址、券、模板后重新确认；不配送；微信/H5支付与原订单续付、取消、整单退款。
7. 并发测试必须在真实测试空间进行：同一模板双人编辑只成功一个；删除与首次绑定竞争不得留下引用已删除模板的商品；报价期间模板变化不得以旧报价建立新订单。
8. 生产仅小范围绑定，观察 CHECKOUT_UPDATE_REQUIRED、PRICE_CHANGED、NOT_DELIVERABLE、FREIGHT_CONFIG_INVALID 等错误码；日志不输出姓名、电话或完整地址。
9. 验收通过后逐步扩展绑定商品。不自动创建8元、15元等示例收费，也不自动指定生产不配送地区。

## 回退

停止新增绑定；按备份恢复受影响商品的配送字段，必要时使用商品服务保存以维护引用锁与版本。菜单可用上述 backupId 调用 rollback({backupId}) 恢复。保留运费模板集合、订单快照和能识别新协议的交易服务，直至所有新协议待付款订单完成或取消；不要直接回退为旧计费服务。历史订单与整单退款始终按原快照金额处理。

## 验证边界

本地回归、构建及隔离组件验证不等于真实云支付验收。尚需在测试空间部署后完成微信开发者工具/真机支付、云数据库并发冲突、菜单权限和退款全链路验证；本次本地实现没有发布云函数、创建生产模板或改动真实商品。
